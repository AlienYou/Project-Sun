# Project Sun 工程开发计划

状态：现行。最后审计：2026-08-16。

## 当前制作目标

当前目标不是扩展更多模式，而是交付一个可重复验证的 **离线 6v6 团队歼灭 Vertical Slice**：玩家能从正确入口进入准备阶段，完成配装，与 11 名 Bot 打完连续多回合，在死亡后观战己方，得到明确的击杀、回合和比赛结果，并能通过正式 UI 开始下一场比赛。

本阶段同时补齐可供策划、关卡、武器和 QA 日常使用的工具链。爆破/拆除、联网、经济、排位和大规模内容生产均在该闭环通过 Gate 4 后再立项，避免在不稳定的离线规则上叠加复杂度。

固定产品规则如下：

- 首个核心模式为 6v6 团队歼灭，单回合一条命，先赢 7 回合获胜。
- 准备阶段选择主武器、副武器、双方配件和一个战术装备，开局后锁定。
- `RoundManager`、`Health` 和受控数据目录分别持有回合、生命和配装合法性权威；HUD、动画和瞄具只消费结果。
- 弹道由相机中心射线选定目标，再由枪口射线验证路径；不得由 HUD 或瞄具模型决定伤害。
- Unity 固定为 `2022.3.51f1c1`，本阶段不升级引擎、URP、Input System 或其他 Package。

## 审计结论

### 已具备，可作为后续基线

- `CombatSlice` 与 `WeaponLab` 两个项目场景，以及对应的场景构建、引用修复和专项设置工具。
- 第一人称移动、Input System 与改键、射击、换弹、主副武器切换、伤害、友军伤害阻止和墙体弹道验证。
- 准备阶段配装、武器/配件数据目录、F-1 手雷和 S-1 感应雷的基础玩法链路。
- 准备、战斗、回合结算、比分、先赢 7 回合、快速测试重开组成的回合状态机。
- 固定容量 `TeamRoster`、双方槽位出生组、玩家 + 11 Bot 阵容、存活统计和己方观战目标查询。
- Bot 的导航、追击、射击、基础巡逻和显式掩体点占用。
- 第一人称视模型、动态附件、ADS、倍率镜 Render Texture、镜片/镜外合成、Clip Probe 与校准工作台。
- HUD、战斗射线调试、WeaponLab 遥测及倍率镜压力测试。
- 2026-08-16 使用现有解决方案完成 C# 编译：0 error；2 条 warning 来自第三方 Low Poly Shooter Pack 示例代码。该结果不替代 Unity Console、Test Runner 和 Play Mode 验收。

### 尚未达到“核心玩法跑通”的缺口

| 优先级 | 缺口 | 当前证据 | 完成条件 |
| --- | --- | --- | --- |
| P0 | 玩家入口与构建不可靠 | Build Settings 的首场景仍是第三方内容展示场景，且没有可发布启动流 | Windows 开发构建直接进入项目启动/CombatSlice，退出与重开路径可用，不依赖编辑器菜单 |
| P0 | 观战链路未完成场景签字 | 代码和文档已实现，但仍标记“待场景验收” | 完成死亡、切换目标、目标再死亡、全队淘汰、下一回合恢复、改键持久化全流程 |
| P0 | 缺少统一战斗事件 | `DamageInfo` 可记录伤害来源，但没有击杀事件、事件序号或稳定参与者数据 | 规则/战斗层发布只读击杀事件；HUD 仅订阅显示；重复死亡不会重复计数 |
| P0 | 比赛结束不是正式玩家流程 | 当前主要依赖开发用 `F8` 重载场景 | 比赛结束面板展示胜方与比分，并提供鼠标/键盘可操作的“再来一局/退出” |
| P0 | 缺少完整回归证据 | 只有 `TeamRosterTests` 一组 EditMode 测试，且文档记录尚未在 Test Runner 正式执行 | 核心纯逻辑测试通过；CombatSlice 冒烟回归有可保存报告；Console 无项目新增错误警告 |
| P1 | 战斗反馈仍偏原型 | 击杀播报、材质命中、枪口/弹壳、音频、战术装备预警不完整 | 玩家能在不看调试面板的情况下理解命中、受伤、击杀、装备威胁和回合结果 |
| P1 | Bot 只够验证系统，不足以支撑稳定对局 | 只有最近目标、基础追击/巡逻和显式掩体点，缺少感知记忆、射击误差和卡死诊断 | 12 人连续对局无明显穿墙、站桩互射、出生拥堵或长时间无交战；关键状态可调试 |
| P1 | 工具分散，缺少统一门禁 | 已有多项 Setup/Workbench 工具，但验证结果分散且依赖人工记忆 | 提供统一 Project Validator 与一键 CombatSlice 验收入口，报告可定位对象和资产 |
| P1 | 战术装备仍使用运行时几何占位 | 文档明确 F-1/S-1 尚无正式 Prefab 表现 | 数据引用项目 Prefab，具备部署/投掷、预警、爆炸、回合清理和缺失引用校验 |
| P2 | 发布工程尚未建立 | 无开发构建门禁、性能预算报告和可审计构建流程 | 可重复生成 Windows Development Build，并保存测试、性能和版本信息 |

## 执行顺序与质量门禁

以下 Gate 必须顺序通过。每一项状态只能使用“未开始 / 实现中 / 待运行验收 / 已通过”；完成代码但未运行验证不能记为“已通过”。

### Gate 0：冻结基线与可重复启动（P0）

目标：任何成员无需了解历史原型，即可打开项目并进入唯一正确的核心验证场景。

交付：

1. 修正 Build Settings：移除或禁用第三方展示场景作为启动项，`CombatSlice` 为当前开发构建入口；如增加 Bootstrap 场景，必须只负责启动与依赖装配。
2. 增加项目级预检，至少检查 Unity 版本、必需 Layer、Input Actions、URP Renderer Feature、Build Scenes、CombatSlice/WeaponLab、关键 Prefab、武器目录及 Missing Script。
3. 将预检接入统一菜单，输出带对象/资产上下文的错误；失败项阻止生成开发构建，不在运行时静默修复。
4. 固化一份 Windows Development Build 操作与产物命名规范；正式测试快捷键默认只在 Development Build 或显式测试开关下可用。

验收：全新打开工程后执行预检为 PASS；从构建产物启动能直接进入项目内容；没有重复相机、AudioListener、玩家或 HUD。

### Gate 1：规则、死亡与比赛闭环（P0）

目标：先把“准备—交战—死亡—观战—结算—下一回合—比赛结束—再开局”变成完整产品流程。

交付：

1. 完成现有 `PlayerSpectatorController` 的 CombatSlice 场景验收并修复发现的问题，覆盖只看己方、防穿墙、改键、目标死亡和回合恢复。
2. 引入只读 `CombatEvent`/`KillEvent` 数据：包含单调事件序号、攻击者、受害者、阵营、伤害类型、时间和必要的自伤/环境伤害语义。事件由战斗权威产生，UI 不反查场景来推断击杀。
3. 增加击杀播报队列、正式回合结算面板和比赛结束面板；快速重开保留为开发功能，正式“再来一局”调用显式比赛重置 API。
4. 明确并测试同时死亡、超时平局、空名册、伤害到达结算边界、重复伤害和最后一人互换等顺序规则。
5. 检查回合重置完整性：生命、弹药、换弹协程、ADS、当前武器、装备次数/实体、Bot 导航/掩体占用、相机、输入和 HUD 全部回到一致状态。

验收：连续完成至少 3 回合和 1 场缩短规则测试赛；任一路径只结算一次；正式 UI 可开始下一场；Console 无项目新增错误或警告。

### Gate 2：枪战可读性与基础 Bot 质量（P0/P1）

目标：玩家不依赖 F10 调试信息，也能理解战斗并得到基本可信的战术对抗。

交付：

1. 完成命中标记、受伤方向、击杀确认、低弹药/换弹状态、敌我轮廓或材质识别；表现只读取战斗事件和权威状态。
2. 建立最小音频/VFX 集：主副武器开火与换弹、枪口火焰、弹壳、墙体/角色命中、受伤、死亡、回合状态和脚步。按生命周期池化高频对象。
3. 为 Bot 增加受控射击误差、反应时间、短期目标记忆、掩体/追击超时和 NavMesh 卡死诊断；参数进入配置，不散落在场景实例。
4. 加入最小移动可读性：Bot 行进、瞄准、受击和死亡表现与实际状态一致；死亡 Collider、Renderer、NavMeshAgent 的启停顺序可验证。
5. 用固定场景连续运行多回合，记录首次交战时间、回合时长、Bot 无目标/卡死数量和帧时间，用数据调整而非凭观感堆逻辑。

验收：12 人连续 10 回合无穿墙伤害、友伤、成员重叠、永久占用掩体或回合无法结束；玩家可凭画面和声音判断主要战斗结果。

### Gate 3：配装、战术装备与内容生产工具（P1）

目标：策划能通过数据和工具安全增加/调整武器、配件与装备，无需修改核心代码或手工修场景引用。

交付：

1. 把 F-1、S-1 运行时几何体替换为 `_ProjectSun` 下的项目 Prefab；数据资产持有 Prefab/表现引用，控制器只负责合法生成与回收。
2. 补齐装备部署预览、可用/不可用提示、投掷/激活/爆炸预警、剩余次数、敌我过滤、遮挡和回合清理验收。
3. 将武器数据生成器升级为“创建 + 校验”工作流：稳定 ID 唯一性、主副武器分类、配件兼容性、倍率为正、Prefab/ADS/瞄具绑定、目录孤儿项和重复项均可报告。
4. 整合 ADS Workbench、Clip Probe、倍率镜报告与运行时组合检查，为每个“武器 × 配件”输出明确 PASS/FAIL，不覆盖人工校准资产。
5. 为 6v6 场景工具增加只读检查模式，校验槽位、出生距离、Wall Layer、NavMesh 可达性、掩体占用配置与双方阵容完整性。
6. 所有编辑器修复操作支持 Undo、标脏和显式保存；批量变更先展示目标列表，第三方原始资源保持只读。

验收：由非程序成员新增一个测试配件或装备，能通过工具完成创建、配置、校验和场景验证；错误配置在进入 Play Mode 前即可定位。

### Gate 4：自动化、性能与 Vertical Slice 签字（P0/P2）

目标：形成可重复的合入门禁，而不是依赖某次人工成功运行。

交付：

1. EditMode 测试覆盖：名册/槽位、回合胜负与超时、配装合法性、武器属性合成、战斗事件去重、友军伤害和数据验证器。
2. PlayMode 冒烟测试覆盖：启动、准备到开局、死亡到观战、回合重置、比赛结束、主副武器切换、装备清理；对必须人工观察的画面项保留清单。
3. 提供统一的验证入口，按“编译 → EditMode → PlayMode 冒烟 → 场景/资产验证 → Development Build”执行并保存机器、提交、Unity 版本和结果。
4. 建立目标 PC 性能预算：1080p 基线、CPU/GPU 帧时间、GC Alloc、内存、Draw Call、倍率镜不同质量档；CombatSlice 和 WeaponLab 分别留档。
5. 完成分辨率矩阵、图形质量档、快速 ADS 压测、10 回合耐久测试和 Windows Development Build 验收。
6. 更新 QA 清单和相关 Authoring 文档，使工具按钮、字段、失败处理与实际实现一致。

最终签字标准：

- 一场 6v6 团队歼灭可以从构建启动到比赛结束并通过正式 UI 再开一局。
- 连续 10 回合无阻断流程的错误、状态泄漏、永久卡死或明显资源增长。
- 核心自动化全绿，Unity Console 无项目新增错误或警告；第三方 warning 单独登记。
- 目标机性能达到已批准预算，倍率镜与 12 人交战不存在不可接受的峰值。
- 当前使用的第三方内容在资产授权台账中有明确状态；未批准资源不得进入发布候选构建。

## 推荐迭代切片

不以日历日期假定团队产能，按可验收成果排期：

1. 迭代 A：Gate 0 + 观战场景签字。
2. 迭代 B：统一战斗/击杀事件 + 击杀播报 + 回合/比赛结束 UI。
3. 迭代 C：回合边界自动化 + 10 回合稳定性修复。
4. 迭代 D：枪战反馈最小集 + Bot 公平性与卡死诊断。
5. 迭代 E：战术装备 Prefab 化 + 武器/配件/场景统一验证器。
6. 迭代 F：PlayMode 冒烟、性能预算、Windows 构建与 Vertical Slice 签字。

每个迭代都必须交付可运行增量、测试结果和文档更新；不得以“代码已写完”替代场景验收。

## 工具链目标形态

| 使用者 | 入口 | 应解决的问题 |
| --- | --- | --- |
| 全员 | Project Validator | 一次检查版本、Layer、场景、URP、输入、关键引用、目录和 Missing Script |
| 关卡 | CombatSlice Validator | 检查双方槽位、出生安全、NavMesh、Wall Layer、掩体点和场景重复对象 |
| 武器/技术美术 | Weapon Presentation Workbench | 装配、腰射、ADS、光轴、镜片、Clip Probe、倍率镜和资源保存 |
| 策划 | Combat Data Validator | 检查稳定 ID、数值范围、配件兼容、目录合法性和战术装备引用 |
| QA | Vertical Slice Test Runner | 执行自动测试、冒烟流程、压力测试并生成带版本信息的报告 |
| 构建负责人 | Development Build Pipeline | 预检通过后生成确定入口、版本号和日志位置的 Windows 构建 |

工具首先提供确定性校验和可定位报告，再提供自动修复。任何自动修复都不得覆盖人工校准、绕过 Undo、修改第三方原始资源或在每帧运行。

## Gate 4 之后的路线

1. **内容 Alpha**：第二把主武器、正式角色/武器/装备表现、工业设施灰盒地图迭代、基础设置与本地化框架。
2. **爆破/拆除模式**：在现有回合接口上增加规则策略、目标物、安放/拆除、切边和模式专属 UI，不复制 `RoundManager` 状态判断。
3. **联网技术切片**：先做两客户端最小服务器权威验证，再扩到配装、投掷物、命中回溯、观战、重连和 6v6；不直接把离线 MonoBehaviour 状态当网络协议。
4. **商业化工程**：匹配/房间、账号、反作弊、崩溃与遥测、内容版本、平台服务、发布流水线和完整可访问性。

## 持续约束

- 所有正式运行时资源位于 `Assets/_ProjectSun`；第三方原始包不直接修改，来源和许可证持续记录。
- `SOCKET_Scope`、`Model`、`AimAnchor`、`LensAnchor` 与 `AttachmentCalibrationRoot` 保持现有职责分离。
- 高频射击、AI、物理和渲染路径使用可复用缓冲区，运行时创建的对象、材质、纹理、Render Texture 和事件订阅必须回收。
- 新增公开 API、序列化字段和工具参数必须有符合项目规范的中文说明；修改工作流时同步 Authoring、Production 和 QA 文档。
- 本文件是范围、优先级与完成状态的唯一事实源。任何新增系统必须说明它服务于哪个 Gate；不能服务当前 Gate 的功能默认延后。
