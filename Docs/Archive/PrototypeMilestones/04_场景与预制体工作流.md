# 场景与预制体工作流

## 本步目标

创建首个可编辑的战斗场景，而不是继续依赖运行时代码生成场地。场景生成器只在首次执行时创建文件，绝不会覆盖已有的 `CombatSlice` 场景、玩家预制体、靶标预制体或材质。

## 执行方式

1. 回到 Unity，等待脚本编译结束，确认 Console 没有红色错误。
2. 在顶部菜单选择 `Project Sun > Build Combat Slice Scene`。
3. 工具会生成并打开 `Assets/_ProjectSun/Scenes/CombatSlice.unity`，同时把它加入 Build Settings。
4. 打开该场景并按 Play。操作与原型一致：WASD、Shift、Space、C、鼠标、R、Q、E、Tab。

## 生成的结构

```text
Assets/_ProjectSun/
  Scenes/CombatSlice.unity
  Prefabs/Characters/Player.prefab
  Prefabs/Characters/TrainingTarget.prefab
  Art/Materials/Prototype*.mat
```

场景 Hierarchy 的 `Combat Slice` 根节点包括：

- `Environment`：地面、墙和掩体。先用于灰盒地图，后续可逐个替换为工业模块预制体。
- `Player`：由 `Player.prefab` 实例化。枪口对象名为 `Muzzle`，不应删除。
- `Training Targets`：靶标预制体实例。
- `Game Systems`：HUD、配装 UI 和场景装配器。不要把玩法对象放进这个节点。

## 导入资源后的替换规则

1. 外部资源保留在原始导入目录，只把经过检查的副本或预制体放入 `Assets/_ProjectSun`。
2. 替换环境时保留或重新添加碰撞体；掩体必须可阻挡射线和角色控制器。
3. 替换第一人称枪时，保留 `Muzzle` 作为枪口 Transform；模型和特效可以替换，名称与层级不需要固定。
4. 替换靶标/敌人时，根对象必须保留 `Health`，命中 Collider 必须是其子节点或根节点。
5. 每次替换后进入 Play Mode 验证：移动、射击命中、换弹、Tab 配装、Q/E 技能和靶标复活。

## 本步验收

- `CombatSlice` 场景可独立打开和运行。
- 删除或禁用旧 `SampleScene` 中的对象不影响 `CombatSlice`。
- 在 Hierarchy 中手动调整一个掩体的位置后，保存、重新打开场景，修改仍存在。
- 不产生第二个玩家、第二台相机或第二套 HUD。
