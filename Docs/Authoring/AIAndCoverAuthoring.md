# AI 与掩体制作规范

状态：现行。当前 AI 用于离线 6v6 战斗与关卡验证，不代表最终联网对手或反作弊方案。

## 阵容与身份

- Bot 必须具有 `Health`、`TeamCombatant` 和 `CombatBotController`，并由 `RoundManager` 纳入稳定名册。
- 进攻方 Bot 使用槽位 1–5，防守方 Bot 使用槽位 0–5；名称排序只是安装阶段的稳定输入，实际身份以 `TeamSlot` 为准。
- Bot 选敌只读取敌方 `TeamRoster` 的存活成员，不能固定追踪本地玩家，也不能把场景查找顺序当成目标优先级。
- 回合准备阶段重置生命和出生姿态；活跃阶段允许战斗；结果阶段冻结。AI 不自行判胜或复活。

## 导航与出生

- 每个出生锚点必须位于或足够接近有效 NavMesh，周围留出角色半径和相邻成员间距。
- 传送时临时停用 `NavMeshAgent`，将目标点投影到邻近 NavMesh，再恢复朝向和导航；禁止直接写正在运行的 Agent Transform 来掩盖配置错误。
- 修改场景道路、墙体、掩体或出生点后，应重新烘焙/验证 NavMesh，并分别检查双方到主要交战区的可达性。

## 掩体点

- `Cover Position` 表示受保护的移动目标，`Peek Position` 表示从掩体侧边恢复视线和交火的位置。
- 同一掩体点同一时间只允许一名 Bot 占用；死亡、切换目标、回合结束或路径失败时必须释放。
- 灰盒自动生成点只用于原型。正式地图由关卡设计师审核位置、朝向、可达性、暴露方向、风险等级和双方可用性。
- 掩体 Collider 必须在 `Wall` Layer，能够同时阻挡角色移动、AI 视线和枪口弹道路径。

## 运行验收

1. 连续三个回合确认 11 名 Bot 都回到自己的稳定槽位，并能从出生点进入 NavMesh。
2. 双方 Bot 能选择最近的合法敌人；目标死亡后会重新选择，不攻击同阵营成员。
3. 让玩家在掩体后消失，确认至少一名相关 Bot 使用可达的 Cover/Peek 点，且多名 Bot 不重叠占用同一点。
4. 从墙体后观察射线调试：AI 必须在实际伤害帧重新验证视线，不能穿墙命中。
5. 全灭只由 `RoundManager` 结算一次；结果阶段 Bot 停止，下一回合恢复生命、位置、导航和掩体占用状态。

F10 调试信息用于开发定位，不得成为 AI 决策输入或 Release 玩家 UI。
