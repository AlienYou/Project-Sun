# Project Sun 文档中心

本目录是 Project Sun 的唯一正式文档入口。Unity 的 `Assets` 目录只保存运行时、编辑器和资源文件，不再保存项目管理文档，避免同一主题出现两套相互冲突的说明。

## 当前基线

- 引擎固定为 Unity `2022.3.51f1c1`，使用 URP 与 Input System；未经专项评估不得升级。
- 首个商业化核心模式为 **6v6 团队歼灭**：单回合一条命，任一方全灭即判负，先赢 7 回合赢得比赛。
- 准备阶段选择主武器、副武器、各自配件与一个战术装备；爆破/拆除是后续复用同一回合基础设施的模式。
- 当前以离线 `CombatSlice` 验证玩法和生产流程；未来联网版本迁移为服务器权威，HUD、动画和客户端表现不参与胜负或伤害裁决。

完整产品与模式约束见[产品与模式基线](Design/产品与模式基线.md)，进度与下一步只以[工程开发计划](ProjectSun工程开发计划.md)为准。

## 权威顺序

1. 产品范围、优先级和完成状态以《工程开发计划》和《产品与模式基线》为准。
2. 资产如何制作、校准和提交，以 `Authoring` 与 `Production` 下的现行规范为准。
3. 系统职责和代码边界以《系统架构与开发边界》及当前实现共同约束；二者不一致时必须记录差异并同步修正文档，不能默默选择其中一份。
4. `Archive` 只保存历史决策和原型里程碑，**不得**作为当前功能、参数或工作流依据。

## 维护规则

- 功能范围、优先级或完成状态变化时，同步更新《工程开发计划》；核心产品规则变化时同时更新《产品与模式基线》。
- 武器、附件、ADS、镜片或校准流程变化时，同步检查两份武器制作规范。
- 输入动作、默认键位、设置持久化或菜单输入阻塞变化时，同步检查输入与设置工作流。
- 阵营、回合、出生或观战流程变化时，同步检查 6v6 名册与出生点规范及 QA 清单。
- 外部资源每次导入、迁移或替换都必须更新授权台账；复制进 `_ProjectSun` 不代表许可已经批准。
- 过时文档优先迁入 `Archive` 并保留原因，不通过并列放置另一份“新版”文档来解决冲突。
