# Project Sun 系统架构与开发边界

状态：现行。本文描述当前离线垂直切片必须保持的职责边界，并为未来服务器权威迁移保留接口。

## 运行入口

- 主验证场景：`Assets/_ProjectSun/Scenes/CombatSlice.unity`。
- 武器专项场景：`Assets/_ProjectSun/Scenes/WeaponLab.unity`。
- 运行时代码：`Assets/Scripts`；仅编辑器使用的工具和测试：`Assets/Editor`。
- 项目资源：`Assets/_ProjectSun`；第三方原始目录不得被直接修改，正式引用应按资源生产规范迁移并登记。

## 权威与表现

| 系统 | 主要职责 | 禁止承担的职责 |
| --- | --- | --- |
| `RoundManager` | 回合状态、比赛比分、存活统计、胜负、配装锁定和合法观战目标 | 不直接绘制 HUD、播放动画或实现武器伤害 |
| `TeamRoster` / `TeamCombatant` | 稳定阵营槽位、成员身份和存活查询 | 不决定回合结果或移动角色 |
| `Health` | 统一伤害与死亡状态 | 不决定武器命中或回合比分 |
| `HitscanWeapon` | 射速、弹药、散布、相机目标射线和枪口物理路径验证 | 不由瞄具模型或 HUD 准星决定命中 |
| `FpsInput` | Input System 动作、玩家设置、改键和测试覆盖 | 不直接修改回合或伤害状态 |
| `PlayerMatchLoadout` / `WeaponInventoryController` | 当局主副武器、配件和装备选择及切换应用 | 不绕过 `RoundManager` 的准备阶段锁定 |
| `WeaponFeedbackController` / 视模型系统 | 后坐、动画、枪口反馈、ADS 和第一人称表现 | 不修改伤害、弹药权威或回合规则 |
| `FpsHud` / 设置与配装 UI | 读取状态并提供玩家交互 | 不直接复活、判胜或强制开启玩法输入 |
| `PlayerSpectatorController` | 死亡后的只读己方相机、音频与切换表现 | 不选择敌方目标、不修改成员生命或回合状态 |

## 射击契约

1. 相机中心射线结合当前散布确定玩家想要命中的目标点。
2. 枪口再向该目标点验证实际物理路径；墙体阻挡时命中墙体，不能穿墙伤害后方目标。
3. 枪口只承担路径验证及 VFX/音频起点，瞄具和 HUD 只负责视觉对齐。
4. `SOCKET_Scope`、`Model`、`AimAnchor`、`LensAnchor` 与 `AttachmentCalibrationRoot` 保持独立职责，具体制作规则见武器资产规范。

## 摄像机与渲染契约

- 世界 Camera 渲染场景并排除 `First Person View` Layer。
- Viewmodel Overlay Camera 只渲染手臂、武器及其表现；当前 FOV 为 `max(94°, 世界相机 FOV + 16°)`，Near Clip Plane 为 `0.01 m`。
- 倍镜只在实际 ADS 且配置有效时更新额外 Render Texture；镜片、准星、镜外弱化和 Eyebox 都属于表现层。
- 死亡观战使用独立 Base Camera，不携带第一人称 Overlay；准备阶段复活后恢复原 Camera 和 AudioListener。

## 生命周期与性能

- 场景安装器只在初始化时完成全局收集和依赖配置；禁止在高频循环中反复 `FindObjectOfType` 或自动修复资源。
- Update、渲染回调、射击和 AI 查询不得无界创建集合、材质、Render Texture 或 GameObject。
- 运行时创建的相机、材质、纹理、Render Texture、事件订阅和临时对象必须在对应生命周期释放。
- 测试快捷键和自动修复必须具有明确的 Editor/Development 开关，不得静默进入 Release 玩法路径。

## 变更验证

- C# 修改后至少通过项目编译，并检查 Unity Console 新增错误和警告。
- 场景、Prefab、武器、附件或渲染配置修改后必须执行对应 Play Mode 验收。
- 纯逻辑优先补 EditMode 测试；输入、组件生命周期和场景交互按风险补 PlayMode 测试。
- 未在当前环境执行的测试必须标记为“待场景验收”，不能仅凭编译通过写成“已完成”。
