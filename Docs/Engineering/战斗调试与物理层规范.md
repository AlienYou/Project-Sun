# 战斗调试与物理层规范

状态：现行。本文约束弹道、AI 视线、相机防穿墙和开发调试使用的 Layer 与诊断信息。

## Layer 策略

| Layer | 用途 |
| --- | --- |
| `Wall` | 地面、边界墙、实心掩体及能够阻挡弹道/视线的关卡几何体。 |
| `First Person View` | 第一人称手臂、武器、附件与相关表现，只由 Viewmodel Camera 渲染。 |
| `Character` | 玩家、Bot 和可受伤害训练目标的命中 Collider。 |
| `Ignore Raycast` | 弹着、辅助标记及不应参与战斗射线的短时表现。 |

`CombatLayers.BallisticMask` 只包含 `Wall | Character`；`WallMask` 用于枪口受阻、观战相机防穿墙及其他只关心实心场景几何体的查询。触发器默认不参与这些验证。

## 弹道与伤害诊断

- 玩家射击先记录相机目标射线，再记录枪口到目标点的物理验证结果；只有最终落到可伤害目标且通过阵营规则时才能扣血和显示命中标记。
- AI 在实际扣血的同一帧重新执行射线，不能沿用旧可见状态；墙体后目标不得受伤。
- `CombatRayDebugOverlay` 在 Editor 或 Development Build 中通过 `F10` 开关，按来源分别显示实际 Collider、Layer 与 `MISS / BLOCKED / VISIBLE / DAMAGE APPLIED`。
- Debug.DrawLine 和面板只是观察结果，不得改变射线、AI 目标或伤害状态；Release 构建不依赖这些调试路径。

## 排查步骤

1. 对墙体中心射击，玩家记录应命中 Wall Layer 并显示 `BLOCKED`，且 HUD 不显示角色命中标记。
2. 隔墙面对可伤害目标射击，枪口路径必须停在墙体；目标生命不下降。
3. 躲到墙后等待 AI，相关 Bot 射线应显示 `BLOCKED`；从边缘露出时才允许变为 `VISIBLE` 或 `DAMAGE APPLIED`。
4. 如果墙体没有阻挡，先检查 Collider 和 Layer，再检查射线掩码；不要通过增加额外伤害判断掩盖错误场景配置。
5. 如果观战相机穿墙，确认对应几何体属于 `Wall`；角色 Collider 和触发器不应为了阻挡观战相机被错误改成 Wall。
