# 输入与设置工作流

状态：现行。项目使用 Unity Input System `1.11.0`；游戏逻辑不读取旧 Input Manager 的 `Mouse X/Y` Axis。

## 输入边界

- `FpsInput` 在运行时建立动作映射，统一提供移动、视角、战斗、技能、配装、设置、调试与观战输入。
- 玩家可见且允许修改的动作进入统一改键菜单；覆盖路径、鼠标灵敏度和 FOV 保存到本机 `PlayerPrefs`。
- `FpsBinding` 枚举值作为本地持久化索引使用。新增值应追加到末尾，避免改变旧索引导致已有玩家设置错配。
- WeaponLab 压力测试使用显式测试覆盖；该覆盖只允许 Editor 或 Development Build，结束或中止时必须恢复真实输入状态。

## 当前默认操作

| 操作 | 默认输入 |
| --- | --- |
| 移动 / 冲刺 / 跳跃 / 蹲伏 | `WASD` / `Shift` / `Space` / `C` |
| 射击 / ADS / 换弹 | 鼠标左键 / 鼠标右键 / `R` |
| 主武器 / 副武器 | `1` / `2` |
| 冲刺技能 / 专注技能 | `Q` / `E` |
| 战术装备 / 交互 | `G` / `F` |
| 配装 / 设置 | `Tab` / `O` |
| 观战上一位 / 下一位 | 左方向键 / 右方向键 |
| 战斗调试 / 快速重开 | `F10` / `F8`（仅开发） |

## 输入启停权威

- 对局中 `RoundManager` 结合回合是否允许玩法、设置菜单是否阻塞以及本地玩家是否存活，计算移动、武器、技能和战术装备的实际启用状态。
- UI 只能声明菜单打开或关闭，不能直接把死亡或准备阶段的玩法组件重新启用。
- `FpsInput` 的动作映射保持监听，使设置菜单、观战切换和开发输入在玩法被冻结时仍能工作；具体玩法组件必须遵守自身启用状态。
- 训练模式没有 `RoundManager` 时，设置菜单保留直接暂停玩法组件的兼容路径。

## 验收

1. 修改一个移动键和一个观战键，退出并重新进入 Play Mode，确认覆盖仍然有效。
2. `Reset Defaults` 后确认默认键位、鼠标灵敏度 `0.12` 和世界相机 FOV `78°` 恢复。
3. 准备阶段及死亡后打开/关闭设置菜单，确认移动、射击、换弹、技能与装备不会被错误启用。
4. 观战阶段确认左右切换仍响应；改键等待期间 ESC 只取消当前重绑定。
5. Console 不出现旧 Input Axis 缺失错误。

正式设置 UI 后续迁移到 UGUI 或 UI Toolkit，并补充冲突检测、独立 ADS 灵敏度、鼠标反转、手柄、本地化和云同步；这些变化不改变 `RoundManager` 的输入权威。
