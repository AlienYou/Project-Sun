## 为什么现在做

当前工程已有武器、附件、第一人称手臂、6v6 名册、出生组、Bot、回合和两个验证场景；`CombatSlice` 已包含基础墙体、掩体、目标和双方槽位，`WeaponLab` 已覆盖 10m、25m、50m 的武器专项测试。因此本任务**不新建第三个对局场景，也不先制作正式美术地图**。

目前项目自有的 `Assets/_ProjectSun/Art/Environment/`、`Art/Audio/`、`Art/VFX/` 仅保留目录占位，F-1 手雷和 S-1 感应雷尚未拥有项目 Prefab 表现。没有这些最小内容时，枪械、瞄具、Bot 和回合系统只能在抽象灰盒中分别验证，难以判断真实对局体验。

本卡只为原型提供“足够可信、可重复测试”的内容，不把资源生产、性能认证或截图归档扩展成每次调参的阻塞流程。

## 原型资源完成标准

一个资源只有同时满足下列条件，才属于本卡的“可用测试资源”：

1. 能回答至少一个明确玩法问题，例如“该掩体是否提供有效射击/遮挡”、“该手雷是否有可理解的部署范围”或“该倍率镜在 25m 是否仍可辨认目标”。
2. 有稳定的项目路径、名称、Prefab 或数据引用；不依赖临时场景对象、运行时查找或未保存的 Prefab Mode 修改。
3. 参与碰撞的环境物具有正确 Collider 与 `Wall` Layer；Bot 相关位置经过 NavMesh 和出生安全验证。
4. 在 `CombatSlice` 或 `WeaponLab` 的目标使用路径中实际运行过；不得只确认 Inspector 引用。
5. 外部来源已登记到[资产授权台账](../Compliance/资产授权台账.md)。未完成许可审核的内容仅能按台账状态用于内部原型，不得标记为可发布资源。

## 工作包

### C01-1：CombatSlice 灰盒可读性

目标：让同一张集成场景能够稳定测试近、中、远距离交火、掩体、墙体遮挡、出生安全和 Bot 路径。

交付：

1. 在 `Combat Slice/Environment` 下建立 `PrototypeContent` 根节点；所有本卡新增场景对象收纳其中。
2. 创建并复用以下项目 Prefab：`PFB_ENV_Prototype_LowCover`、`HighCover`、`SolidWall`、`DoorwayWall`、`CrateBarricade`。
3. 每个 Prefab 根节点 `Scale = (1,1,1)`，命名、材质、Collider、`Wall` Layer 和静态标记明确；可见网格与实际碰撞轮廓一致。
4. 在 CombatSlice 使用场景标识清楚标注 10m、25m 对局参考距离；50m 与倍率镜校准继续由 WeaponLab 负责，并为双方出生区验证不可直接互视的最小缓冲区。
5. 重新烘焙或验证 NavMesh，检查 12 名成员出生、寻路、掩体占用与枪口遮挡。

当前工具入口：`Project Sun > Prototype Content > Setup CombatSlice Greybox`。该工具只创建缺失的 5 个项目 Prefab、`Environment/PrototypeContent` 下的 `C01_*` 实例和新增高掩体的 Cover Anchor；再次执行会保留已有实例与锚点的人工位置调整。

验收：本地玩家可在一局中从三种距离与两种掩体高度测试 AR-4/HG-3；Bot 不会出生重叠、卡在新增掩体中或穿过实心墙。

### C01-2：F-1 与 S-1 原型 Prefab

目标：让两种战术装备拥有能区分部署、激活、威胁和清理状态的项目视觉载体。

交付：

1. 建立 `Assets/_ProjectSun/Prefabs/Tactical/`，放置 `PFB_TAC_F1_FragGrenade` 与 `PFB_TAC_S1_SensorMine`；数据资产只引用项目 Prefab。
2. F-1 至少具有投掷中的网格、落地/爆炸提示和回合结束回收；S-1 至少具有部署态、警戒态和触发态的材质或灯光区分。
3. 运行时实体不能引用第三方展示场景对象；实例化、回收和回合清理由现有战术装备控制器保持权威。
4. 缺失 Prefab、错误 Layer、敌我过滤或回合遗留实体必须有可定位错误或验证结果。

验收：玩家能在 CombatSlice 内通过画面辨认两种装备，任一方无法借装备伤害队友，回合切换后没有遗留实例。

### C01-3：最低战斗反馈集

目标：在不进入正式音频/VFX 制作的前提下，让玩家不用调试面板就能分辨关键战斗结果。

交付：

1. 开火、角色命中、墙体命中、受伤方向、死亡和战术装备预警各有明确且不混淆的原型反馈。
2. 高频效果使用池化或现有可回收路径；不得在每次射击时无界创建材质、纹理或对象。
3. 音频优先使用可审计的临时资源；无合法来源时只保留静默/简单合成占位，不把来源不明素材加入运行时依赖。
4. 反馈表现只消费伤害、战斗和装备权威状态，不从 HUD 或渲染对象反向决定命中和胜负。

验收：在不打开 F10 调试信息时，玩家能区分“打中墙体”“打中角色”“自己受伤”“队友死亡/回合结算”四类结果。

## 资源来源与目录约束

```text
Assets/_ProjectSun/
├─ Art/
│  ├─ Environment/Prototype/     # 原型环境网格、材质与贴图
│  ├─ Audio/Prototype/           # 已登记来源的原型 SFX
│  └─ VFX/Prototype/             # 项目原型 VFX
├─ Prefabs/
│  ├─ Environment/Prototype/     # 可复用掩体与墙体 Prefab
│  └─ Tactical/                  # F-1、S-1 等项目装备 Prefab
└─ Data/Weapons/Tactical/        # 战术装备数据资产
```

- `Assets/_ProjectSun/Art/ThirdParty/Infima` 中的副本仍按 `EXT-002` 状态管理；它可作为内部原型参考，但不能因为已迁移就被视作获准发布。
- 新增外部资源先登记台账，再导入或复制；来源、作者、许可或再分发条件缺失时，不能作为正式运行时资源提交。
- 本卡优先使用项目自制灰盒、现有合法项目资源或已核验资产。需要购买/下载的环境、音频或 VFX 包先形成候选清单，由负责人确认许可证后再导入。
- 不修改任何第三方原始资源；需要调整时创建 `_ProjectSun` 中的项目副本并保留来源与许可证记录。

## 执行顺序

1. 先完成 C01-1，确保场景空间、碰撞、NavMesh 和出生点可以稳定承载测试。
2. 再完成 C01-2，使手雷和感应雷不再依赖运行时几何占位。
3. 完成 C01-3 的最小反馈后，进行一场缩短规则的 6v6 对局测试，记录武器、掩体、Bot 与装备的首轮问题。
4. 将首轮问题拆分为“规则/结算”（进入迭代 B）和“战斗可读性/Bot”（进入后续迭代），不在本卡无限追加优化。

## 完成定义

- C01-1 至 C01-3 均在目标场景实际验证；新增资源没有 Missing Script、材质、Collider 或数据引用。
- 至少完成一局缩短规则的 6v6 测试，覆盖主副武器、一个非倍率瞄具、F-1、S-1、死亡观战、回合切换和装备清理。
- 场景、Prefab、数据资产及对应 `.meta` 均保存；`git diff` 中不包含第三方原始资源或无关的 ADS 校准。
- 记录一段简短的运行结果、已知问题和后续归属即可；只有复现缺陷或负责人明确要求视觉佐证时才归档截图，日常调参与本卡完成不要求建立正式验收报告。
- 资源来源和许可证状态已同步到[资产授权台账](../Compliance/资产授权台账.md)。
