# Project Sun 产品与模式基线

状态：现行。最后更新：2026-08-13。

本文记录已经确认的产品范围。它回答“正在做什么”；具体实现进度由[工程开发计划](../ProjectSun工程开发计划.md)维护，历史原型方案不覆盖本文。

## 产品定义

| 项目 | 当前决定 |
| --- | --- |
| 类型 | 第一人称、回合制、团队战术射击游戏 |
| 首发平台 | Windows / Steam |
| 首个核心模式 | 6v6 团队歼灭 |
| 后续模式 | 爆破/拆除，复用队伍、回合、配装、出生与伤害基础设施 |
| 美术方向 | 近未来工业设施，强调敌我识别、真实比例和低视觉噪声 |
| 输入 | 键盘鼠标优先；正式版手柄支持后续评估 |
| 引擎 | Unity 2022.3.51f1c1 LTS + URP |
| 联机原则 | 服务端权威；客户端不裁决伤害、命中、配装合法性或胜负 |

## 团队歼灭规则

- 每个阵营最多 6 名成员；当前离线切片为本地玩家加 5 名进攻方 Bot，对抗 6 名防守方 Bot。
- 每回合只有一条命，回合进行中不复活；任一阵营全部淘汰后，另一方赢得本回合。
- 先赢 7 回合的一方赢得整场比赛，不使用累计击杀数作为直接胜利条件。
- 当前默认准备时间 6 秒、战斗时间 180 秒、结果展示 7 秒；这些是可调配置，不改变上述核心规则。
- 战斗超时时默认比较双方存活人数；人数相同则平局。未来加入爆破目标后，由模式规则定义更高优先级的目标结算。
- `F8` 重新加载当前测试比赛仅用于开发，不属于正式玩家流程。

## 配装范围

- 当局开始前通过配装菜单选择一把主武器、一把副武器、两者各自的兼容配件，以及一个战术装备。
- 对局开始后锁定配装；客户端未来只提交武器和附件标识，由服务器目录重建并验证合法配置。
- 配件应形成明确取舍，而非无代价叠加数值；可视附件与数值定义分层，但正式交付必须同时完成玩法和表现验收。
- 当前战术装备包括 F-1 破片手雷与 S-1 感应雷，后续装备继续使用同一配装和回合重置边界。

## 产品支柱

1. 枪战优先：弹道、命中、后坐力、动画和声音反馈必须清晰且可验证。
2. 公平可信：墙体遮挡、友军规则、回合胜负和未来网络同步必须来自明确权威。
3. 可反制技能：技能创造战术选择，但不能替代枪法；必须有可预判或可躲避的应对方式。
4. 生产可重复：武器、配件、角色和地图资源通过统一命名、配置、工具和验收流程进入项目。
5. 商业可发布：许可证、性能、崩溃、可访问性、设置和本地化均属于产品质量，而非最后补做的外围工作。

## 当前不做

- 在团队歼灭闭环稳定前，不提前实现爆破目标、经济系统或复杂赛制。
- 在离线规则和接口稳定前，不直接堆叠匹配、排位、反作弊或账号服务。
- 不制作开放世界、大逃杀、载具战斗或无限成长数值系统。
- 不使用来源不明、不可商用或未经许可的品牌、武器型号和第三方素材进入发布构建。
- 不让 HUD、动画、瞄具模型或客户端表现成为伤害和回合规则权威。
