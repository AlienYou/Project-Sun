# 场景与预制体工作流

状态：现行。本文描述可编辑场景和项目 Prefab 的维护边界；早期运行时生成 `SampleScene` 的说明已经归档。

## 正式工作场景

| 场景 | 用途 |
| --- | --- |
| `Assets/_ProjectSun/Scenes/CombatSlice.unity` | 6v6 团队歼灭、回合、AI、HUD、配装和观战的集成验证。 |
| `Assets/_ProjectSun/Scenes/WeaponLab.unity` | 武器、附件、ADS、镜片、动画和压力测试的专项验证。 |

场景和 Prefab 必须保存可审查的序列化引用。运行时安装器可以配置依赖和创建明确的表现辅助对象，但不能每帧搜索或静默修复缺失资源。

## 目录与层级

```text
Assets/_ProjectSun/
├─ Scenes/
├─ Prefabs/
│  ├─ Characters/
│  ├─ Environment/Prototype/
│  ├─ Tactical/
│  └─ Weapons/Attachments/
├─ Art/
└─ Data/
```

- `Combat Slice/Environment`：灰盒或正式环境，实心遮挡物使用 `Wall` Layer 和有效 Collider。
- `Combat Slice/Environment/PrototypeContent`：C01 原型资源包专属根节点；仅放置以 `C01_` 命名的可复用灰盒实例、距离参考标识与其辅助对象，不能与既有 Cover、出生组或目标混放。
- `Player`：由项目 Player Prefab 实例化；关键相机、视模型、武器和输入引用由 `FpsPlayerInstaller` 暴露。
- `Game Systems`：回合、HUD、配装和场景安装器；不要在这里放置需要参与战斗碰撞的角色或环境。
- `Team Spawn Groups`：双方固定槽位出生锚点，只定义位置和朝向。
- 武器和附件的稳定节点遵循对应 Authoring 规范，不通过场景内临时重命名绕过制作契约。

## 编辑规则

1. 创建、移动、重命名或删除 Unity 资源时同时处理 `.meta`，保留 GUID 和现有序列化引用。
2. 修改 Prefab 或场景前先确认是否处于 Prefab Mode、Play Mode 或 Workbench 临时预览；临时 ADS 姿态不可保存进正式 Prefab。
3. 编辑器工具修改场景、Prefab 和配置时必须支持 Undo、标脏和明确保存；工具重复执行不得覆盖人工调整的有效数据。
4. 第三方原始目录保持只读；需要修改或进入运行时依赖的内容复制到 `_ProjectSun`，并更新授权台账和第三方声明。
5. 环境替换后验证 Collider、Wall Layer、NavMesh、出生点、AI 视线和弹道遮挡；视觉模型正确不等于玩法碰撞正确。
6. `Project Sun > Prototype Content > Setup CombatSlice Greybox` 只创建缺失的项目 Prefab 和 `C01_*` 场景实例，首次创建支持 Undo；再次执行必须保留已存在实例与 Cover Anchor 的人工位置调整。执行后仍需进入 Play Mode 验证 NavMesh、出生和弹道，工具成功提示不等于运行验收通过。

## 提交验收

- 关闭并重新打开场景或 Prefab 后，人工修改仍然存在，没有 Missing Script、材质或引用。
- CombatSlice 不产生第二个玩家、重复 HUD、重复世界相机或 AudioListener。
- 场景相关工具重复执行不会移动已经人工校准的出生点、附件或 ADS 资源。
- 在 Play Mode 检查与改动相关的回合、AI、武器、附件或渲染路径；只通过编译不能替代场景验收。
- 提交只包含当前任务资产及对应 `.meta`；用户尚未纳入范围的校准数据保持在工作区。
