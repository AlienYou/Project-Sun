# 机器人与导航验证

## 本步目标

用三个离线防守机器人验证地图是否具备可行的路线、视线、掩体和目标区压力。它们是灰盒验证工具，不是最终线上 AI 或反作弊方案。

## 启用方式

1. 确认 `CombatSlice` 已执行过回合系统升级。
2. 在 Unity 顶部菜单选择 `Project Sun > Add Defender Bots To Combat Slice`。
3. 工具会生成：

```text
Assets/_ProjectSun/Prefabs/Characters/TrainingDefender.prefab
Assets/_ProjectSun/Art/Materials/PrototypeDefender.mat
Combat Slice/Defenders/Defender 01-03
Combat Slice/Game Systems/RuntimeNavMeshBuilder
```

4. 运行 `CombatSlice`。机器人会在各自的目标区附近守卫；进入其视野后会追击并以低频率射击。玩家被击倒后三秒会回到出生点。

## 验证清单

- 三个机器人均能在场地中移动，而非停留、穿墙或掉出地图。
- 从两条主路和侧路接近目标区，至少存在一条能避开直接交火的路径。
- 掩体可打断机器人视线；离开掩体后，机器人可重新发现玩家。
- 击倒机器人后，五秒内在原守卫区域重新出现。
- 玩家死亡后，三秒内重生，移动与武器输入恢复正常。
- 连续运行十分钟，Console 没有红色错误、导航代理错误或重复 NavMesh 警告。

## 资源替换边界

现在的红色胶囊体只是验证对象。替换为正式角色时，保留机器人根节点上的 `NavMeshAgent`、`Health`、`CombatBotController`；把模型、Animator、命中 Collider 和音效作为子对象接入。不要把正式角色逻辑依赖在示例包的脚本上。

## 后续

完成导航验证后，优先迁移到 Unity Input System 并实现可保存的按键重绑、灵敏度和 FOV 设置。这样玩家控制不再依赖项目级旧输入轴配置，适合后续菜单与商业发布。
